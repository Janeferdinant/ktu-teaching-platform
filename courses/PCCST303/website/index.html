Module 1 • Recurrence & Complexity KTU High-Yield • 9 Marks

Problem 1: Solve the Recurrence Relation T(n) = 2T(n/2) + Θ(n) using Master Theorem & Substitution

Given: A divide-and-conquer algorithm partitions an array of size n into 2 equal halves, recursively solves each half, and performs linear work cn for combining results.

Step 1: Identify Parameters for Master Theorem:
General form: T(n) = a T(n/b) + f(n)
Here: a = 2, b = 2, and f(n) = Θ(n).
Step 2: Compute the Critical Exponent log_b(a):
log_b(a) = log_2(2) = 1
Therefore, the watershed function is n^{log_b(a)} = n^1 = n.
Step 3: Compare f(n) with n^{log_b(a)}:
Since f(n) = Θ(n^{log_b(a)} * log^k(n)) with k = 0, this falls strictly into Master Theorem Case 2.
Solution: T(n) = Θ(n^{log_b(a)} * log^{k+1}(n)) = Θ(n log n)

Memory Footprint Derivation: In Sparse Matrix 3-tuple storage for an m × n matrix with k non-zero elements, memory reduction ratio is R = (3k) / (m × n). When k = 0.05(mn), memory consumed is only 15% of standard 2D arrays.

Module 2 • Memory Management KTU High-Yield • 9 Marks

Problem 2: External Fragmentation & Doubly Linked List Memory Footprint

Given: A dynamic heap of 1000 KB contains free holes of sizes 120 KB, 80 KB, 160 KB, and 140 KB separated by allocated segments. A new request arrives for a contiguous block of 200 KB.

Step 1: Calculate Total Free Memory:
Total Free Space = 120 + 80 + 160 + 140 = 500 KB
Step 2: Evaluate Allocation Feasibility & Fragmentation:
Maximum contiguous block available = 160 KB < 200 KB.
Hence, request FAILS despite 500 KB total free memory available.
External Fragmentation Ratio = 1 - (Max Contiguous Free Block / Total Free Memory) = 1 - (160 / 500) = 0.68 (68%)
Step 3: Doubly vs Singly Linked List Node Overhead:
On a 64-bit architecture (8-byte pointer, 4-byte integer payload with 4-byte alignment padding):
• Singly Linked List Node = 4 (data) + 4 (padding) + 8 (next) = 16 Bytes
• Doubly Linked List Node = 4 (data) + 4 (padding) + 8 (next) + 8 (prev) = 24 Bytes
Overhead increase = (24 - 16) / 16 = +50% memory consumption per node.
Module 3 • Trees & Binary Heaps KTU High-Yield • 9 Marks

Problem 3: Mathematical Proof of O(n) Build-Heap Time Complexity

Given: A complete binary tree of n elements has height h = ⌊log_2 n⌋. At any height h, the maximum number of nodes is ⌈n / 2^{h+1}⌉.

Step 1: Formulate Total Work Done by Max-Heapify:
A call to Max-Heapify on a node at height h takes O(h) time.
Total Time T(n) = Σ_{h=0}^{⌊log n⌋} ⌈n / 2^{h+1}⌉ * O(h) = O(n * Σ_{h=0}^{∞} h / 2^h)
Step 2: Solve the Infinite Arithmetico-Geometric Series:
Let S = Σ_{h=0}^{∞} h / 2^h = 0/1 + 1/2 + 2/4 + 3/8 + 4/16 + ...
Multiply by 1/2: (1/2)S = 0/2 + 1/4 + 2/8 + 3/16 + ...
Subtract: S - (1/2)S = 1/2 + 1/4 + 1/8 + 1/16 + ... = (1/2) / (1 - 1/2) = 1
Therefore: (1/2)S = 1 ==> S = 2.
T(n) = O(n * S) = O(n * 2) = O(n)

Conclusion: Converting an arbitrary array into a binary heap via bottom-up heapify runs in strictly linear O(n) time, not O(n log n).

Module 4 • Hashing & Collision Resolution KTU High-Yield • 9 Marks

Problem 4: Hash Probe Sequence Calculations (Linear vs Quadratic vs Double Hashing)

Given: Hash table of size m = 11 with hash function h1(k) = k mod 11. Secondary hash function for double hashing is h2(k) = 7 - (k mod 7). Insert keys: 43, 26, 72, 85, 39.

Step 1: Linear Probing: h(k, i) = (h1(k) + i) mod 11
• k = 43: h(43,0) = 43 mod 11 = Index 10
• k = 26: h(26,0) = 26 mod 11 = Index 4
• k = 72: h(72,0) = 72 mod 11 = 6 = Index 6
• k = 85: h(85,0) = 85 mod 11 = 8 = Index 8
• k = 39: h(39,0) = 39 mod 11 = 6 (COLLISION with 72!)
    i = 1: (6 + 1) mod 11 = 7 (Free) ==> Index 7.
Step 2: Double Hashing Probe for k = 39:
h1(39) = 6, h2(39) = 7 - (39 mod 7) = 7 - 4 = 3.
i = 0: index 6 (Collision)
i = 1: (6 + 1*3) mod 11 = 9 mod 11 = Index 9.
Double hashing eliminates primary and secondary clustering.
Expected Unsuccessful Probes E(U) = 1 / (1 - α) where load factor α = n/m = 5/11 = 0.454 ==> E(U) = 1.83 probes

Real-Life Industry Engineering Applications

Production systems engineering architectures bridging theoretical data structures to modern enterprise platforms.

Module 1 • Systems Architecture

Web Browser History & Multi-Level Undo Engine

Modern web browsers (Chrome V8) and graphical editors (Figma, Photoshop) utilize dual LIFO stacks (Back-Stack and Forward-Stack) to enable instantaneous constant-time O(1) state undo and redo navigation while bounding memory buffers.

Module 2 • Operating Systems

Linux Kernel SLAB Allocator & Video Ring Buffers

The Linux kernel memory manager implements SLAB allocation caches (using First-Fit / Best-Fit algorithms) to eliminate external fragmentation. High-throughput video streaming engines (Netflix, YouTube) use Circular Linked Buffers for zero-copy streaming.

Module 3 • Autonomous Routing & DBs

OSPF Network Routing & Database B+ Tree Indexing

Enterprise internet backbones deploy Dijkstra's algorithm over graph meshes for low-latency packet routing. Relational database engines (PostgreSQL, MySQL InnoDB) rely on balanced B+ Tree search structures to guarantee O(log n) disk block queries.

Module 4 • Distributed Systems

Distributed In-Memory Cache & Compiler Symbol Tables

Distributed caching platforms (Redis, Memcached) use consistent hashing matrices with MurmurHash3 to distribute terabytes of session keys across cluster nodes with minimal key re-mapping. Compilers utilize hash tables for instantaneous symbol lookup.
